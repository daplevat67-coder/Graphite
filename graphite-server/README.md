# Graphite Tunnel 1

Экспериментальный TCP-туннель для GRAPHITE VPN 0.3. Нужны Python 3.11+, TLS 1.3 и сертификат для домена, которому доверяет Android. В приложении нужен Android 10 или новее. Используй отдельный тестовый VPS, если хочешь попробовать протокол через интернет.

## Self-hosted установка по SSH

Для этого способа нужен Linux VPS с systemd, Python 3.11+, `flock`, доступом root по SSH, доменом, направленным на VPS, и готовым TLS-сертификатом для домена. Пути к сертификату и ключу относятся к VPS. Входящий TCP 8443 должен быть разрешён в настройках VPS и его провайдера.

Сначала установи доверие к SSH-ключу хоста обычным подключением, сверив отпечаток с панелью провайдера. Затем из каталога `graphite-server` на ПК выполни:

```sh
bash deploy.sh root@IP_СЕРВЕРА vpn.example.org \
  /etc/letsencrypt/live/vpn.example.org/fullchain.pem \
  /etc/letsencrypt/live/vpn.example.org/privkey.pem
```

Последние два необязательных аргумента задают порт Graphite и порт SSH, по умолчанию 8443 и 22. Установщик запускает отдельный сервис systemd, проверяет TLS и токен локальным запросом, затем печатает ссылку для импорта. Сохраняй ссылку приватно. Повторный запуск обновляет сервис с прежним токеном. После обновления сертификата перезапусти `graphite-tunnel.service`, чтобы загрузить новый сертификат. Доступность порта с телефона проверь после установки.

## Ручной запуск сервера

Создай файл доступа в каталоге, доступном только пользователю сервера.

```sh
umask 077
python3 -c 'import secrets; print(secrets.token_urlsafe(32))' > graphite-token.txt
python3 server.py --listen 0.0.0.0 --port 8443 \
  --cert /path/to/fullchain.pem --key /path/to/privkey.pem \
  --token-file graphite-token.txt
```

Для подключения открой в GRAPHITE **Протоколы → Graphite Tunnel → Создать подключение** и вставь `graphite://TOKEN@vpn.example.org:8443`. Подставь содержимое файла ключа и домен из сертификата. Сохрани профиль и нажми «Подключить» в списке серверов. Ссылка даёт доступ к прокси, поэтому передавай её только доверенному пользователю. Для смены ключа обнови файл и перезапусти сервер.

## Как устроен протокол

1. Клиент проверяет сертификат и имя сервера через системное хранилище доверия. Используется TLS 1.3.
2. После TLS клиент посылает четыре ASCII-байта `GTP1`, байт операции и 32 байта ключа. Операция 0 проверяет токен и наличие свободного рабочего слота в момент запроса. Она не резервирует слот и не проверяет подключение к назначению. Операция 1 открывает TCP-соединение и добавляет порт и длину адреса по два байта big-endian, затем ASCII-адрес. Сервер отвечает одним байтом статуса, где 0 означает успех, а 1 — отказ (в том числе если сервер занят).
3. В каждом направлении полезные данные разбиты на кадры с двухбайтовой длиной big-endian. Максимум 16 384 байта. Нулевая длина означает завершение передачи в одном направлении.
4. Android использует существующие TUN и Xray для маршрутизации. Внутренний SOCKS5 принимает только локальное подключение со случайным логином и паролем на время подключения. Между телефоном и VPS используется Graphite Tunnel 1.

## Границы первой версии

Один TLS-сеанс на TCP-поток. Системные DNS-запросы A/AAAA перенаправляются через DNS-over-TCP. Остальные типы обычных UDP DNS-запросов получают отказ. Прочий UDP, QUIC и ICMP не поддерживаются. Первичное разрешение имени самого VPS происходит через физическую сеть. Автоматического переподключения при смене сети пока нет.

Сервер по умолчанию соединяется только с публичными адресами и сверяет каждый разрешённый IP до соединения. `--allow-loopback` предназначен для локального стенда и требует `--listen 127.0.0.1`. Первая версия не проходила независимый аудит. TLS обеспечивает шифрование, а собственный формат задаёт аутентификацию и передачу кадров.

## Лимиты и фильтрация назначений

Лимит применяется при приёме TCP, до TLS. Сервер одновременно допускает до 8 соединений до авторизации с одного IP и до 96 всего. У TLS-рукопожатия и чтения заголовка с токеном отдельные таймауты по 3 секунды. До 96 авторизованных TCP-туннелей учитываются отдельно. Клиенты за одним NAT делят лимит по IP. При заполнении общего лимита новые подключения отклоняются. Таймаут простоя туннеля составляет 180 секунд без передачи данных в обоих направлениях.

Сервер блокирует стандартные префиксы NAT64 `64:ff9b::/96` и `64:ff9b:1::/48`. Если сервер использует собственный префикс NAT64, ограничьте доступ к внутренним сетям также на уровне исходящего трафика сервера.
